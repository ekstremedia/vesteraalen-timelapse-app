## Session 2: Stale Image Refresh Trigger

### Features Implemented

#### Backend Stale Image Refresh Integration
The `/api/app/cameras` endpoint now automatically triggers stale image refresh. When the app polls for cameras, the backend checks for stale images and dispatches capture jobs if needed.

**How it works:**
1. App calls `GET /api/app/cameras` (on init, polling, or resume)
2. Backend returns camera data immediately
3. Backend also checks which cameras have images older than 1 minute
4. If stale, dispatches jobs to request new photos from Raspberry Pi cameras
5. When Pi responds, backend processes image and broadcasts via WebSocket
6. App receives WebSocket event and updates UI in real-time

**Implementation:**
- Added `triggerStaleImageRefresh()` method to `AppCamerasController`
  - Rate limited: once per minute globally
  - Only runs in production
  - Doesn't slow down API response

**Rate limiting:**
- Global: 1 check per minute (via `app_cameras_stale_check` cache key)
- Per camera: 60s cooldown after dispatch (via `camera_refresh_dispatched_{id}` cache key)
- Queue check: skips if job already pending for camera
